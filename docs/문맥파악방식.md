# 누적 컨텍스트 Refine 계획

## 배경

현재 center-commit 방식은 4.0s 청크 + 1.0s overlap으로, 각 청크가 거의 독립적으로 디코딩됨.
이전 컨텍스트를 누적하여 SenseVoice에 전달하면 정확도가 현저히 증가할 수 있음.

### 현재 방식 (sliding window)

```
"가나다"를 보고  "가나"
"나다라마"를 보고 "다라"
"라마바사"를 보고 "마바"
```

각 청크는 1.0s overlap만 공유. 문맥 부족으로 음소/단어 경계 판단이 불안정.

### 제안 방식 (accumulating context)

```
"가나다"를 보고       "가나"
"가나다라마"를 보고    "다라"
"가나다라마바사"를 보고 "마바"
```

이전 오디오 전체를 컨텍스트로 제공 → 더 많은 문맥으로 정확도 향상.

---

## 핵심 설계 결정: 전체 덮어쓰기 (re-decode) 방식 채택

### 비교

| | A: 조각 유지 (commit-once) | B: 전체 덮어쓰기 (re-decode) |
|---|---|---|
| 동작 | 새 stride 구간만 commit, 이전 불변 | 매번 전체 re-decode, 이전 결과 교체 |
| 이전 구간 개선 | X | O |
| SubtitleStore 변경 | 적음 | 큼 |
| flicker 위험 | 없음 | 있음 (안정화 장치 필요) |

### 결정: B (re-decode) + frozen 안정화

이유: 누적 컨텍스트의 핵심 이점이 **이전 구간도 개선**되는 것.
A 방식이면 이전 구간 정확도는 현재와 동일 → 컨텍스트 누적의 의미 반감.

## 구현 계획

### 1. `_context_buffer` 누적 (`refine_stage.py`)

```python
# 현재
self._overlap_buffer: np.ndarray | None  # 1.0s만 보관

# 변경
self._context_buffer: np.ndarray | None  # 전체 누적
self._max_context_samples: int           # threshold (samples)
```

`_feed_center_commit()` 변경:
- 현재: `full_chunk = overlap(1s) + new(3s)` = 4s 고정
- 변경: `full_chunk = context_buffer + new(3s)` = 점점 증가
- SenseVoice에 full_chunk 전체를 넘기고, **전체 디코딩 결과로 confirmed_text 교체**

### 2. SubtitleStore 변경: frozen + mutable

```python
    def apply_refine(self, full_decode: str):

        # frozen과 full_decode 앞부분이 일치하는지 확인
        # mutable 구간을 새 결과로 대체
```

frozen 기준: **2회 이상 re-decode 해도 결과가 동일한 구간** → 안정화 판단 → freeze.

효과:
- 초반 구간은 2~3번 보정 후 확정
- 최근 구간은 계속 개선
- 화면 flicker는 최근 구간에만 발생 (사용자 시선이 있는 곳이라 자연스러움)

### 3. Threshold 기반 Trimming

```yaml
# default.yaml
refine:
  chunk_sec: 4.0
  trim_sec: 0.5
  max_context_sec: 30.0   # 새 파라미터
```

`_context_buffer`가 `max_context_sec` 초과 시:
- `_prev_committed_text`에서 **문장 경계** 탐색
- 해당 시간 지점까지의 오디오를 trim
- frozen 구간은 이미 확정이므로 안전하게 제거 가능

### 4. 문장 경계 탐지 (단계적)

**Phase 1 (간단):** 정규식 기반
```python
SENT_BOUNDARY = re.compile(r'[.?!。？！~]\s+')

def _find_trim_point(self, text: str) -> int:
    m = SENT_BOUNDARY.search(text)
    return m.end() if m else len(text) // 2  # fallback: 절반
```

**Phase 2 (필요시):** kss(Korean Sentence Splitter) 등 문장 분리 모델 도입.

### 5. 시간↔텍스트 매핑

```python
@dataclass
class CommittedSegment:
    text: str
    start_sec: float
    end_sec: float

self._committed_segments: list[CommittedSegment] = []
```

trim 시 segments 앞쪽 제거 → 해당 `end_sec`까지의 audio를 `_context_buffer`에서 잘라냄.

### 6. Config 추가 (`default.yaml`, `settings.py`)

```yaml
refine:
  max_context_sec: 30.0
```

## 리스크 & 고려사항

1. **SenseVoice 입력 길이 제한**: ~30s까지 안정적. `max_context_sec`를 이 범위 내로 설정
2. **디코딩 시간 증가**: 입력 커지면 RTF 증가 → 1차 자막과의 gap 모니터링 필요
3. **메모리**: 30s @ 16kHz = ~960KB — 무시할 수준
4. **Trimming 부정확**: 문장경계 없는 긴 발화 시 fallback 필요 (시간 기반 강제 trim)

## 구현 순서

1. `refine_stage.py`: `_overlap_buffer` → `_context_buffer` 누적 전환
2. `refine_stage.py`: re-decode 시 전체 결과 반환하도록 변경
3. `subtitle_store.py`: frozen/mutable 구조 도입, `apply_refine()` 교체 로직
4. `config`: `max_context_sec` 추가
5. `refine_stage.py`: threshold 초과 시 문장 경계 기반 trimming
6. 테스트: 긴 오디오(2분+)로 정확도 및 latency 비교
